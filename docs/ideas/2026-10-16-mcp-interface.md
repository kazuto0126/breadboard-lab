# 構想：給 AI 工具用的接口（MCP 伺服器與指令列工具）

- 日期：2026-10-16
- 狀態：**未開發**（使用者 2026-10-16 要求先記下來，之後再決定要不要做）
- 要做的話：照一般子專案的流程，先和使用者確認用途與第一版的工具，寫規格（`docs/superpowers/specs/`），再實作。

---

## 1. 想解決什麼

現在只能在網頁上一步一步點。若有給 AI 工具（Claude Desktop、Claude Code 等）用的接口，AI 可以直接用文字完成：

- 「用 74LS00 做一個 XOR，放到麵包板上」
- 「檢查這個電路哪裡錯，告訴我怎麼改」
- 「算這張邏輯圖的真值表，轉成麵包板再跑 AI 佈線」

做完的電路存成檔案，再到網頁「匯入 JSON」打開來看。

## 2. 為什麼適合（評估結果）

1. 核心引擎與網頁分開：佈線、檢查、模擬、邏輯圖轉換都是不碰瀏覽器的純函式（`tsconfig.json` 不含 DOM 型別，佈線本來就在 Web Worker 跑）。
2. 已經有公開函式：`src/index.ts`（`validateCircuit`、`autoRoute`、`autoPlaceAndRoute`、`compileSimulation`、`settle`…），`tests/api.test.ts` 確認它們都在。
3. 電路與邏輯圖都是 JSON 檔，讀檔時已經會檢查格式並說明錯在哪裡。
4. 結果可以自己驗證：轉換後逐列模擬比對真值表（`verifyBreadboard`）已經有了。

## 3. 限制

- 網站是 GitHub Pages 上的靜態網頁，沒有伺服器：MCP 伺服器要在使用者自己的電腦上跑（需要 Node.js），較適合老師、助教、開發者；只用網頁的學生用不到。
- 不會即時同步到正在開的網頁：AI 改的是檔案，要看結果就匯入（或用第 6 節的「用連結開啟」）。
- AI 自己決定元件插在哪個孔容易出錯：工具要會檢查位置、回傳原因，並提供「找空位」。
- 大電路的 AI 佈線可能要十幾秒：工具要能設時間上限。

## 4. 做法比較

| 做法 | 適合誰 | 工作量 | 評語 |
|---|---|---|---|
| A. 指令列工具（例如 `npx breadboard-lab check 檔案.json`） | 開發者、Claude Code | 小 | 最快有成果 |
| B. 本機 MCP 伺服器（stdio），和 A 共用同一套工具 | Claude Desktop、Claude Code、其他 MCP 用戶端 | 中（約一個子專案） | **建議**：工具名稱與參數清楚，AI 不容易用錯 |
| C. 雲端 MCP（要架伺服器） | 不想安裝的人 | 大，有主機成本 | 目前不划算 |
| D. 讓 AI 直接操作開著的網頁 | 想看 AI 即時動手 | 大，要改網頁架構 | 之後再考慮 |

建議先做 A + B，用檔案進出。

## 5. 第一版工具（草案）

| 工具 | 做什麼 |
|---|---|
| `load_circuit` | 讀電路檔，回傳摘要（板子、元件與每隻腳的孔位、Net） |
| `check_circuit` | 錯誤與警告，附離線白話解說與建議改法 |
| `list_parts` | 元件庫與腳位 |
| `place_component` | 放元件（檢查位置，不合法時回傳原因）；搭配「找空位」 |
| `add_wire`、`remove_item` | 接線、刪除 |
| `save_circuit` | 存成網頁能匯入的 JSON |
| `auto_route` | AI 標準佈線（可選擇可不可以移動 IC），回傳線數、交叉、接不通的原因 |
| `simulate` | 設定開關後讀 LED、7 段顯示器 |
| `truth_table` | 邏輯圖的真值表 |
| `build_logic` | 從閘、方塊、常數與接線建立邏輯圖 |
| `logic_to_breadboard` | 轉換 + 佈線 + 逐列比對真值表，一次完成 |

## 6. 可以一起做的小功能

- 網頁「用連結開啟電路」：AI 做完給一個網址（電路壓縮後放在網址 `#` 後面），點開就看到結果，不用手動匯入。
  要注意網址長度上限；大電路仍用匯入。
