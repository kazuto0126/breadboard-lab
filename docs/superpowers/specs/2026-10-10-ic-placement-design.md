# 可以移動 IC 的佈線模式（子專案 8）設計規格

- 日期：2026-10-10
- 狀態：已完成（2026-10-11）
- 來源：使用者 2026-10-10 的新需求第 6 項「新增另一種佈線模式，允許 AI 移動 IC 元件，但不要移動最終輸出（LED 及其電阻）和輸入（指撥開關）」
- 前提：子專案 7 的佈線標準（直線跳線＋轉接排，`docs/superpowers/specs/2026-10-10-routing-standard-design.md`）

---

## 0. 目的

「AI 標準佈線」不移動元件，IC 放得離 LED、開關很遠時，線就又多又長。新模式「AI 佈線（可移動 IC）」先幫每顆 IC 找一個比較好的位置，
再用子專案 7 的規則佈線，讓學生照著插的線少一點、短一點。原本的「AI 標準佈線」不變。

## 1. 規則（使用者確認）

| 項目 | 規則 |
|---|---|
| 誰會動 | 只有 IC（元件類別 `ic`：74LS 系列，之後的 NE555 也算）。電源、接地、指撥開關、按鈕、時脈、電阻、LED 都不動 |
| 可以放哪裡 | IC 原本那塊板所在的 Board Group 裡**任何一塊板**（使用者選擇「貼在一起的板都可以」） |
| 方向 | 可以維持原方向，也可以**轉 180 度**（使用者選擇「可以轉 180 度」）。不轉 90 / 270 度（跨不了凹槽） |
| 合法位置 | 每支腳都插在空的孔上、而且是五孔排（不是電源軌）；同一顆 IC 的腳各在不同的排（等於跨在凹槽上）；腳與本體不碰到其他元件的腳與本體 |
| 不能短路 | IC 的腳插進的那一排，如果已經有其他元件的腳，那些腳必須和這支腳屬於原本的同一個 Net |
| 連接不變 | 每支腳原本和哪些腳相連，移動後還是一樣（以「腳」為準，不以「孔」為準） |
| 好壞順序 | 和佈線相同：接不完的 Net 少 → 交叉少 → 線少 → 總長短 |
| 不會變差 | 一定和「IC 都不動」的佈線結果比較；沒有比較好就不移動。同分時留在原位 |

## 2. 怎麼保持連接不變

### 2.1 原本的 Net

用原電路（元件＋使用者的導線）分析出的 Net（`extractNets`）。每個 Net 記下：它的腳（`PinRef`）、它用到的電源軌（Net 的 `groupIds` 裡種類是 rail 的群組；
電源軌不會動，維持是這個 Net 的終端）。只當「轉接」用的五孔排（沒有腳、只有使用者的線經過或停留）不保留。

### 2.2 搬移後的電路

給定一組搬移（哪顆 IC 搬到哪塊板、哪個錨點、哪個方向），產生一個「搬移後的電路」：

- 元件：搬過的 IC 換成新位置，其他元件沿用原本的物件。
- 導線：換成**描述連接關係的導線**。每個 Net 把它在新位置的終端排（腳所在的排＋它的電源軌）依序串起來，每兩排一條線，端點取那一排的第一個格點。
  這些線只用來告訴佈線器「哪些排要接在一起」，不會出現在結果裡；`extractNetsWith` 只看端點所在的群組，所以端點插在腳上也沒關係。

這樣佈線器（`autoRoute`）、合法性檢查（`checkRoutingLegality`）與評分完全沿用，不另外寫一套。

### 2.3 短路檢查

搬移後的電路要通過：用它分析出的 Net，和原本的 Net 以「腳」為單位比較，分組完全相同（同一組的腳還是同一組，不同組的腳不會被併在一起）。
候選位置在 1 節的「不能短路」規則下本來就會相同；這一項是最後的保險，不相同就丟掉這個候選。

## 3. 找位置

### 3.1 候選位置

對一顆 IC（其他 IC 固定在目前的位置），列出 1 節所有合法的位置：同一個 Board Group 的每塊板、每個孔當錨點、旋轉 0 與 180 度，
用 IC 的封裝算出腳與本體的格點，逐一檢查。順序固定：板子 ID、y、x、旋轉角度。

### 3.2 粗估

每個候選位置算一個很快的估計，只算和這顆 IC 有關的 Net（其他 Net 不受影響）：

- 每個 Net 的終端排依元件內部導通分簇（`terminalClusters` 的規則），簇與簇之間用最小生成樹相連。
- 兩排之間的估計：兩排的孔兩兩比較，取最小的「線數 × `wire` ＋ 轉接數 × `via` ＋ 曼哈頓距離 × `distance`」；
  兩孔在同一列或同一行算 1 條線、0 個轉接，否則算 2 條線、1 個轉接（權重沿用 `RoutingWeights`）。
- 不考慮障礙與交叉（交給下一步的實際佈線）。

### 3.3 實際佈線比較

依粗估由小到大取前 `candidatesPerIc` 個（預設 3；同分依 3.1 的順序），每個都產生搬移後的電路、跑一次 `autoRoute`，
用 1 節的好壞順序和目前最好的結果比較。比較的起點是「IC 都不動」的結果（搬移後的電路，搬移為空）。

候選位置的佈線把協商輪數上限設成「`candidateIterations` 和『IC 都不動』用掉的輪數的兩倍，取大的那個」（不超過原本的上限）：
佈不出來的位置會一直協商到上限（加法器每個約 5 秒），要很快放棄。實作時量到：沒有這個上限時加法器要 20 秒，有了之後約 6 秒，結果相同。

### 3.4 輪流

- IC 的順序：接到的 Net 腳數多的先，同分依元件 ID。
- 每顆 IC 輪流做 3.1–3.3，某顆 IC 換到更好的位置就立刻採用，下一顆 IC 以它的新位置為準。
- 一整輪都沒有改善就停；最多 `maxPasses` 輪（預設 2）。
- 總時間超過 `timeBudgetMs`（預設 20 秒）就停，回傳目前最好的結果。

結果固定：同一個電路算兩次結果相同（時間上限只在很大的電路上才會碰到）。

### 3.5 設定

`RoutingConfig` 加一段 `placement: { candidatesPerIc: 3, maxPasses: 2, timeBudgetMs: 20000, candidateIterations: 30 }`，`mergeConfig` 一併合併。

## 4. 輸出與套用

- `RoutingResult` 加選擇性的 `moves?: IcMove[]`：

  ```ts
  interface IcPlacement { boardId: string; anchor: { x: number; y: number }; rotation: Rotation }
  interface IcMove { componentId: string; from: IcPlacement; to: IcPlacement }
  ```

  新模式一定有這個欄位（沒搬動就是空陣列）；「AI 標準佈線」沒有。
- `applyRouting(circuit, result)`：有 `moves` 時一併把 IC 放到新位置（沒搬的元件沿用原本的物件），導線換成結果的導線。
- Undo：佈線結果是一次 commit，按一次 Undo 位置與導線一起還原。
- 比較資料（`Comparison`）：
  - 原本的 `components` 仍是佈線前的元件陣列。
  - 新增 `appliedComponents`：套用了有搬移的結果後的元件陣列（沒搬動時為 null）。
  - 「比較是否過期」改成：板子相同，而且目前的元件陣列是 `components` 或 `appliedComponents` 其中之一。
- 「切回手動接線」：導線換回佈線前的手動導線，**元件也換回佈線前的位置**。

## 5. 畫面

| 地方 | 改法 |
|---|---|
| 「自動佈線」選單 | 在「AI 標準佈線」下面加「AI 佈線（可移動 IC）」 |
| 工具列 | 「⚡ AI 標準佈線」旁加一個「⚡ 可移動 IC」按鈕（窄螢幕只出現在選單） |
| 計算中的畫面 | 標題改成「AI 佈線（可移動 IC）計算中…」，說明「找 IC 位置 → 直線跳線佈線 → 合法性檢查」。順便把原本過時的「A* 正交搜尋」改成「直線跳線搜尋」 |
| 結果卡 | 列出搬了哪些 IC，例如「U1：F10 → F22（轉 180 度）」，多塊板時加板子 ID；沒有搬動時寫「IC 已經在最好的位置，沒有移動」 |
| 動畫 | 搬過的 IC 在動畫期間加醒目的外框，原位置畫虛線外框；導線在 0.6 秒後才開始一條一條出現 |
| 比較畫面 | 左邊：原位置＋手動導線；右邊：新位置＋AI 導線 |
| 說明對話框、README | 加一段說明這個模式 |

錨點的名稱用第 1 腳所在的孔名（`holeName`）。

## 6. 程式結構

| 檔案 | 內容 |
|---|---|
| `src/core/icPlacement/relocate.ts` | 原本的 Net、搬移後的電路（2.2）、腳的分組比較（2.3）、套用搬移到元件陣列 |
| `src/core/icPlacement/candidates.ts` | 一顆 IC 的所有合法位置（3.1） |
| `src/core/icPlacement/estimate.ts` | 粗估（3.2） |
| `src/core/icPlacement/autoPlace.ts` | `autoPlaceAndRoute(circuit, overrides)`：3.3–3.4，回傳含 `moves` 的 `RoutingResult` |
| `src/types/routing.ts` | `IcPlacement`、`IcMove`、`PlacementConfig`、`RoutingResult.moves` |
| `src/core/routing/apply.ts` | 套用搬移 |
| `src/workers/*` | 請求加 `moveIcs?: boolean`；Worker 依此呼叫 `autoPlaceAndRoute` 或 `autoRoute` |
| `src/state/store.ts` | `runAutoRoute(purpose, { moveIcs })`、`Comparison.appliedComponents`、過期判斷、切回手動、動畫的搬移資訊 |

核心（`src/core`）不能用 `src/editor` 的程式；候選位置的檢查用 `CircuitIndex`（腳與本體佔用表）與麵包板的節點資料自己做。

## 7. 測試與驗收

- 候選位置：跨凹槽、不壓元件、不短路（同排有別的 Net 的腳就不行、同 Net 的腳可以）、可以換到同組的另一塊板、不會換到別組的板、可以轉 180 度、不轉 90 度。
- 搬移後的電路：腳的分組和原本相同；搬移為空時佈線結果和 `autoRoute(原電路)` 相同的線數、交叉、總長。
- 範例電路（`src/editor/examples.ts` 全部）：新模式全部佈完、通過合法性檢查，結果依 1 節的順序不比「AI 標準佈線」差；
  套用後 Check Circuit 沒有錯誤；模擬的 LED 結果和移動前相同（加法器、驗收電路）。
- 一個「IC 離 LED 很遠」的電路：新模式一定搬動 IC，而且線數或總長比不動時少。
- 結果固定：同一個電路算兩次相同。
- Store：套用後 Undo 一次還原位置與導線；切回手動接線也還原位置；比較畫面左右兩邊的 IC 位置不同。
- 端對端：從選單執行「AI 佈線（可移動 IC）」，結果卡出現搬移資訊、所有線都是直線；Undo 後 IC 回到原位。

## 8. 不做

- 移動 IC 以外的元件、旋轉 90 / 270 度、讓使用者鎖住某顆 IC（之後需要再加）。
- 把 IC 搬到沒有貼在一起的另一組麵包板。
- 同時一起搜尋很多顆 IC 的組合（模擬退火等）；IC 很多時以後再考慮。
