# 接線規則：不斜、不交叉、轉彎分兩條、不跨過 IC（子專案 39）設計規格

- 日期：2026-10-20
- 狀態：已實作（分支 `feat/wiring-rules`，建在子專案 38 的分支上）
- 出處：使用者 2026-10-20：「線要轉彎一定要區分成兩條，直接一條線走直角不被接受，兩條線不可以重疊類似十字交叉也不行，
  線也不可以跨過 IC 上下都不行，一定要垂直，不可斜向拉線。若是這些規則與原本牴觸，就依新規則為準。尤其是 MCP 接口的部分也要按照這樣去寫。」

---

## 1. 規則（以後所有的導線都要符合）

1. **只能水平或垂直**：每條導線是一條水平或垂直的直線，不能斜著拉。
2. **轉彎要分成兩條**：一條線不能走直角（舊檔案裡由好幾段組成、會轉彎的「路徑導線」不合規則）。
   要轉彎就接到一排相通的孔（五孔排），再從同一排的另一個孔接下一條線。
3. **不重疊、不交叉**：兩條線不能重疊，也不能十字交叉（在兩條線的中段相交）。
4. **不跨過 IC**：線不能從 IC 上面經過，橫的、直的都不行（IC 本體蓋住的範圍，包括跨在凹槽上方的部分）。

## 2. 和以前的差別

| 規則 | 以前 | 現在 |
|---|---|---|
| 手動接線、MCP `add_wire` 斜線 | 可以 | 不行 |
| 交叉 | AI 佈線盡量避免（每處扣很多分）、手動接線可以、檢查不報錯 | 一律不行 |
| 會轉彎的路徑導線（舊檔案） | 檢查不報錯 | 檢查報錯 |
| 線經過 IC | 已經不行（元件本體、腳都是障礙） | 不變，補上測試與說明 |
| 重疊 | 已經不行 | 不變 |

## 3. 要改的地方

1. **手動接線**（拉新線、拖曳端點）與 **MCP `add_wire`**：斜線、和別的線交叉都不能接，說明原因
   （「導線只能水平或垂直；要轉彎請分成兩條線」「不能和導線 w3 交叉（在 E12）」）。經過 IC 的說明寫出「元件（例如 IC）」。
2. **AI 標準佈線、可以移動 IC 的佈線、轉成麵包板**：交叉從「扣分」改成「不准」：協商時交叉算衝突（和重疊一樣要排開），
   嚴格模式不准交叉；合法性檢查多一項「交叉」，沒通過的 Net 算排不完。
3. **Check Circuit**：斜線、會轉彎的路徑導線、兩條線交叉都列為錯誤，標出那條線（舊檔案、範例也會被檢查到）。
4. **錯誤解說建議的線**、「導線說明」：建議的線一樣要水平或垂直、不交叉（共用手動接線的檢查，會自動符合）。
5. **MCP**：伺服器說明、`add_wire`、`auto_route`、`check_circuit` 的說明寫上規則；`logic_to_breadboard` 佈線沒有完成時
   不再存下「還沒佈線的麵包板」（那些預定的連線是元件腳之間的直線，常常是斜的、會交叉），改成不寫入檔案並說明哪幾條沒接好。
6. 畫面上的說明文字、README、MCP 設定說明頁。

## 4. 不變的地方

- 手動接線一個孔可以插好幾條線（使用者沒有提；AI 佈線本來就是一孔一線）。
- 電阻、LED 這類兩腳元件兩腳中間可以讓線經過（使用者只提 IC）。
- 網頁「轉成麵包板」佈線沒有完成時照舊顯示預定的連線與結果卡（讓使用者看到哪些沒接好）；這些線會被 Check Circuit 標成不合規則。

## 5. 驗收

- 手動接線、MCP 接斜線、交叉的線、經過 IC 的線都被拒絕，說明原因。
- Check Circuit 對斜線、轉彎的路徑導線、交叉報錯；合規的電路不報。
- AI 佈線的結果沒有交叉（量測的每個電路交叉 0 處），轉換量測不變差太多（記錄在 CHANGELOG）。
- 範例電路符合新規則（或在 AI 佈線前故意不合規、佈線後合規）。
