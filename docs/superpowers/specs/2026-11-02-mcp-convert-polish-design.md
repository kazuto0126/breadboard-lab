# 用 MCP 接大電路時碰到的問題（子專案 55）設計規格

- 日期：2026-11-02
- 狀態：完成（PR #86，和子專案 54 一起，已發布）
- 出處：使用者 2026-11-02 用 MCP 接課本圖 8-8 後，要求「接的時候碰到的問題，專案本體和 MCP 都優化」。

---

## 1. 碰到的問題與改法

| 問題 | 改法 |
|---|---|
| `new_circuit` 寫到還不存在的資料夾（`circuits/xx.json`）時失敗（ENOENT） | 寫檔前先建立資料夾 |
| `logic_to_breadboard` 不能多給時間；差 1 條也只能換設定再試 | 新參數 `seconds`（10–300 秒）；回覆寫出這次用了幾秒（上限幾秒） |
| 接不完時的建議和這次的設定無關（已經自動選板還建議 `board: "EIC1106"`、已經加了下拉電阻還建議加） | 照這次的設定建議：先 `seconds`（加倍，至少 120、最多 300），顯示器每段一顆電阻時建議共用、指定板子時建議自動、照種類對應時建議只用 NAND，最後是簡化邏輯圖；已經用了的設定不再建議 |
| 大電路轉換要一分多鐘，AI 工具看不到進度，也可能等太久而逾時 | 有 `progressToken` 時每一批佈線送一次 `notifications/progress`（「佈線中：第 3 批，2 種擺法（已經 45 秒）」）；只用一個執行緒時也一批一批跑，中間能回報 |
| 自動存檔的 hook 把最上層的實驗腳本和電路檔也 commit 進去 | 只收已追蹤的檔案與專案資料夾（src、tests、e2e、docs、scripts、public、.github、.claude）裡的新檔案；`circuits/` 加進 `.gitignore` |

專案本體的部分（轉換時間不夠）在子專案 54。

## 2. 測試

- 回覆的建議：自動選板、照種類對應、共用電阻時不建議已經用的設定；每段一顆電阻、指定板子、只用 NAND、給了 200 秒時建議共用、自動、300 秒。
- 伺服器：`new_circuit` 建立兩層新資料夾；`logic_to_breadboard` 給 `seconds: 10` 時回覆「用了 N 秒（上限 10 秒）」並收到進度。
