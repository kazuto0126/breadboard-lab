# 回答裡的孔位可以點、導線解說（子專案 11）設計規格

- 日期：2026-10-11
- 狀態：已完成（2026-10-11）
- 需求文件：第十六章（AI 負責分析、解釋，不直接畫線）、第三十七章（AI Circuit Assistant）
- 前一份：`2026-10-10-ai-followup-design.md`（錯誤卡上的「問 AI」）第 7 節「之後可以做」的前兩項

---

## 0. 目的

1. 學生看 AI 的回答時，不用自己去板子上找「A10 在哪裡」：回答裡的孔位與「U1 第 3 腳」點了就在板上閃一下。
2. 學生點一條線（特別是 AI 標準佈線產生的線），可以知道這條線在接什麼、為什麼要經過轉接排；
   不用網路就有基本說明，有疑問再「問 AI」。

## 1. 決定（使用者確認）

| 項目 | 決定 |
|---|---|
| 這次做的 AI 功能 | 回答裡的孔位可以點、導線解說（使用者 2026-10-11 選擇）。不做整次佈線的總說明、不做對照題目檢查 |
| 導線解說的入口 | 點一條線，右邊「導線」區塊下面（使用者選擇）。不用網路的說明一定顯示；下面有「問 AI」 |
| 孔位辨識 | 程式自己在回答文字裡找孔位，不要求 AI 用特殊格式；只有電路裡真的存在的孔或腳才變成可以點 |
| 點了之後 | 畫面移過去（現有的 `focusPoints`）＋板上那個孔閃一下（約 2 秒）；右邊面板與選取不變，對話留著 |
| 同一時間的對話 | 還是只有一段：在錯誤卡上問和在導線上問會互相取代（和現在換錯誤時一樣） |
| 自動修改 | 不做。AI 只解釋、只建議 |

## 2. 孔位與腳位變成可以點（`src/editor/aiLinks.ts`，純函式）

`linkify(circuit, text): Array<string | AiLink>`，`AiLink = { text: string; points: GridPoint[] }`：把文字切成一般文字與可以點的片段。

依序辨識（前面的優先，已經用掉的字不再辨識）：

1. **腳位**：`U1 第 3 腳`、`U1 的第 3 腳`、`U1第3腳`、`U1 pin 3`（大小寫不拘）。元件 ID 要在電路裡、腳號要在元件定義裡；
   點了閃那隻腳所在的孔。整段文字（含「第 3 腳」）變成可以點。
2. **接線柱**：`紅柱`、`黑柱`、`黃柱`、`綠柱`、`紅色接線柱`（四種顏色）。只有電路裡有 EIC-1106 時才辨識；
   有多塊 EIC-1106 時用第一塊（依 `circuit.boards` 順序）。單獨一個「紅」字不辨識（「紅色 LED」不能變成連結）。
3. **孔位**：可選的板子前綴 `b2:`，加上 `parseHoleName` 接受的名稱：`A10`、`T+10`、`B-30`（含全形減號 `B−30`）、`P3+12`、`2-F30`。
   - 前後不能緊接英文字母、數字、`+`、`-`、`:`（`74LS00`、`ABC10`、`A10B` 都不辨識）。
   - 和電路裡某個元件 ID 相同的字（例如 LED 的 `D1`、電容的 `C1`）**不當孔位**：學生和 AI 說 D1 通常是指元件。
   - 有前綴：只在那塊板上找。沒有前綴：只有一塊板有這個孔名時才辨識（多塊 MB-102 時 `A10` 不知道是哪一塊，不變成連結；`1-A15` 只有 EIC-1106 有，可以）。
   - 找不到的孔（`Z99`、`A99`）不辨識，維持一般文字。

使用的地方：AI 的回答（`AskAi` 的 `Gemini：` 訊息，串流中也即時辨識）、導線說明（第 3 節）。
錯誤卡的離線解說原本就用 `{0}` 標孔位、已經可以點，這次只把點了的動作改成第 4 節的「移過去＋閃」。

## 3. 導線說明（不用網路，`src/editor/explain/wire.ts`，純函式）

`explainWire(circuit, wireId): WireExplanation | null`

```ts
interface WireExplanation {
  net: Net | undefined;            // 這條線所在的 Net（沒有接到任何東西時 undefined）
  summary: string;                 // 第一句：屬於哪個 Net、這段連線接哪裡到哪裡
  chain: Array<{ wireId: string; text: string }>; // 這段連線依序的每一條線；text 寫兩端各接了什麼
  why: string | null;              // 為什麼不一條線直接接（只有 AI 標準佈線、而且這段連線不只一條線時）
}
```

文字裡的孔位與腳位用 `holeLabel` 與「U1 第 3 腳」的寫法，畫面上再用第 2 節的 `linkify` 變成可以點。

### 3.1 這段連線（chain）

把這個 Net 的導線看成「排（導通群組）之間的邊」。從選到的線往兩個方向延伸：
經過的排如果**沒有元件腳、不是電源軌或接線柱、而且剛好接兩條這個 Net 的線**（典型的轉接排），就繼續往下一條線走；
否則停下，那一排就是這段連線的一端。

兩端的說法：

| 那一排 | 說法 |
|---|---|
| 有元件腳 | 「U1 第 3 腳（1Y）」；同一排有好幾隻腳就用「、」連起來 |
| 電源軌 | `RAIL_TEXT`（「上方的 + 電源軌」「P3 的 + 電源軌」） |
| 接線柱 | 「紅色接線柱（+5 V）」「黑色接線柱（GND）」「黃色接線柱」 |
| 沒有腳、但這裡分岔（接三條以上） | 「F18 那一排（從這裡分成 3 條線）」 |
| 沒有腳、只接這一條線 | 「F18 那一排（沒有接到別的東西）」 |

- `summary`：「這條線屬於 NET_3（訊號），負責把 U1 第 3 腳（1Y）接到 R1 第 1 腳。」
  只有一條線時改成「這條線把 U1 第 3 腳（1Y）接到 R1 第 1 腳，屬於 NET_3（訊號）。」
  電源 Net 用「VCC（電源）」「GND（地）」。線的兩端都沒有接到任何腳或電源時：「這條線兩端都沒有接到元件或電源。」
- `chain` 每一條線：「F12 → F18：F12 和 U1 第 3 腳同一排；F18 那一排是空的，當成轉接排。」
  端點那一排是轉接排就寫「當成轉接排」，有元件腳就寫「和 U1 第 3 腳同一排」，電源軌寫「插在上方的 + 電源軌」。
  選到的那一條在畫面上標「（本條）」。

### 3.2 為什麼不一條線直接接（why）

只在這條線是 AI 標準佈線（`source: 'auto'`）、而且這段連線有兩條以上時計算。拿掉這段連線的線之後，看兩端的排：

1. 兩端的排之間**沒有**任何一對空孔在同一列或同一欄 →
   「兩端不在同一列、也不在同一欄，一條直線接不到，所以經過轉接排轉彎。」
2. 有在同一列或同一欄的空孔，但每一條直線都不合法（`straightWireProblem`）→
   「兩端雖然可以排成一直線（例如 F12 → F25），但中間會經過 U2 的腳（G18），所以改走轉接排。」（舉第一個候選的原因）
3. 有合法的直線 →
   「其實也可以一條線直接接（例如 F12 → F25）。AI 標準佈線為了少和別的線交叉、讓出位置給其他連線，選了經過轉接排的走法。」

手動接的線不寫 `why`（是學生自己決定的走法）。

## 4. 點了之後：移過去並閃一下

- store 新增 `flash: { points: GridPoint[]; id: number } | null` 與 `flashPoints(points)`：
  先做現有的 `focusPoints(points)`，再設定 `flash`（`id` 每次加一）；2 秒後如果還是同一個 `id` 就清掉。
- 畫布用 `Ring` 畫琥珀色的圈，加上 CSS 動畫（放大縮小閃三次）；`data-testid="flash-ring"`。
- 不改選取、不換右邊面板分頁、不進 Undo。
- 離線解說的孔位按鈕、導線說明、AI 回答的連結都用 `flashPoints`。

## 5. 導線的「問 AI」

### 5.1 畫面

導線區塊（`PropertyPanel` 的 `case 'wire'`）下面加 `WireExplanationCard`（`data-testid="wire-explanation"`）：

```
─── 這條線在做什麼 ─────────────────
這條線屬於 NET_3（訊號），負責把 U1 第 3 腳（1Y）接到 R1 第 1 腳。
這段連線共 2 條線：
1. F12 → F18（本條）：F12 和 U1 第 3 腳同一排；F18 那一排是空的，當成轉接排。
2. J18 → J25：J25 和 R1 第 1 腳同一排。
為什麼不一條線直接接：兩端不在同一列、也不在同一欄，……
─── 問 AI（Gemini）────────────────
[為什麼這樣走？] [可以換一種接法嗎？] [實際插線時要注意什麼？]
```

- 說明裡的孔位與腳位可以點（第 2、4 節）。這段連線的其他線（第 2 條的 `J18 → J25`）點了也只是閃，不換選取。
- 「問 AI」沿用 `AskAi` 的畫面（金鑰、建議問題、輸入框、停止、錯誤、免責聲明），只換建議問題與送出的內容。

### 5.2 對話的歸屬

`useAi.chat` 的 `issue` 改成 `topic`：

```ts
type AiTopic = { kind: 'issue'; issue: CircuitError } | { kind: 'wire'; wireId: string };
```

- 同一段對話 = 同一個電路（參照）＋ 同一個 topic（錯誤用參照比較；導線用 ID 比較）。
- 其他行為不變：改了電路就清掉、換 topic 就開新的一段、同一時間只有一段。

### 5.3 送給 Gemini 的內容

第一則訊息 = 電路摘要 + 【學生正在看的導線】 + 【AI 標準佈線的規則】 + 【學生的問題】：

```
【學生正在看的導線】
w3（AI 標準佈線）：F12 → F18
這條線屬於 NET_3（訊號），負責把 U1 第 3 腳（1Y）接到 R1 第 1 腳。
這段連線共 2 條線：
1. F12 → F18（本條）：……
2. J18 → J25：……
為什麼不一條線直接接：……

【AI 標準佈線的規則】
每條線都是水平或垂直的直線，兩端插在孔上；要轉彎時停在一排相通的孔（轉接排），下一條線從同一排的另一個孔出發。
轉接排只用空的五孔排或這個 Net 自己的排。每個孔最多插一條線；線不能經過元件腳、元件本體、別條線的端點，也不能和別條線重疊。
優先順序：最少交叉，其次線的條數少，再其次總長度短。元件的位置不會被移動（除非學生選了「可以移動 IC」）。
```

手動線把第一行的「AI 標準佈線」換成「學生手動接的線」，不附規則段落，也沒有「為什麼不一條線直接接」。

### 5.4 系統指示更新（錯誤與導線共用）

- 第一句改成：「你是數位邏輯實驗課的助教，幫學生理解麵包板電路的錯誤與接線。」元件清單不再寫死（摘要裡已經有每個元件的名稱與說明）。
- 孔位寫法依電路裡的板子型號：MB-102 用 A10、T+10；EIC-1106 用 `1-A15`（插孔區號-列欄）、`P2+12`（電源軌）、紅柱 / 黑柱（接線柱）。
  多塊板時孔位前面加板子 ID（`b2:A12`）。
- 新增一條：「提到孔位或元件腳時，照摘要的寫法寫（例如 F12、U1 第 3 腳），學生可以點它在板上找到位置。」
- 電路摘要的孔位規則（`HOLE_RULE`）依電路裡有的板子型號產生：只有 MB-102 時和現在一樣；有 EIC-1106 時加上它的三個插孔區、P1–P5 與接線柱的說明。
