- 出處：`docs/ideas/backlog.md`「給其他 AI 工具用的接口」；評估在 `docs/ideas/2026-10-16-mcp-interface.md`；

## 1. 為什麼做、給誰用

子專案 23 的 MCP 伺服器只能在這個原始碼資料夾裡、用 Claude Code 跑；原始碼 repo 是私人的，別人拿不到。
這次讓**任何支援 MCP 的 AI 工具**都能用同一套工具，並且加上**真值表題目**的工具。

- 使用的人：會寫程式、電腦上已經有 Node.js 的人（使用者 2026-10-19 選的方向：「比較適合會寫程式的人」）。
  學生照常用網頁，不受影響。
- 主要的 AI 工具：Cursor、VS Code 的 Copilot、Gemini CLI；也附 Claude Desktop 與 Claude Code 的設定。
- 做成功的樣子：在 Cursor 或 Gemini CLI 裡說「出一題 3 個輸入的多數決，畫邏輯圖、轉成麵包板、和題目比對」，
  AI 能一路做完，存成網頁可以「匯入 JSON」打開的檔案。

## 2. 目標、不做、絕對不行

**目標**

1. 伺服器打包成**一個檔案**（`breadboard-lab-mcp.mjs`），只要 Node.js 就能跑，不用下載原始碼、不用 `npm install`。
2. 這個檔案和網站一起放到公開的 `kazuto0126/breadboard-lab-site`，從網址下載。
3. 網站上有一頁**設定說明**（繁體中文）：下載、每個 AI 工具照著貼的設定、第一次可以怎麼問。
4. 新增真值表題目的工具：寫入題目、看題目與化簡結果、從題目產生邏輯圖、和邏輯圖 / 麵包板比對。
5. 讓 AI 能看資料夾裡有哪些電路檔（Claude Desktop 等工具自己看不到資料夾）。

**這次不做**

- 發布到 npm（要申請帳號；之後要的話再加，打包好的檔案可以直接用）。
- Claude Desktop 點兩下就能安裝的擴充功能包。
- 雲端版 MCP（要架伺服器、有費用）、讓 AI 直接操作開著的網頁、用連結開啟電路。

**絕對不行**

- 公開原始碼或作者的 Email：網站 repo 只放建好的檔案；發布前檢查打包檔裡沒有 Email，有就停止發布。
- 讀寫指定資料夾以外的檔案，或蓋掉不是電路檔的檔案（沿用子專案 23 的規則）。
- 弄壞現有的用法：原始碼資料夾的 `.mcp.json`（Claude Code）、`npm run mcp` 照常可用，現有 14 個工具的名稱與參數不變。

## 3. 資料夾

- 子專案 23：伺服器只能讀寫**原始碼專案資料夾**裡的 `.json` 檔。打包版沒有原始碼資料夾，改成**工作資料夾**：
  - 啟動參數 `--folder <路徑>`（相對路徑從目前資料夾算起）；沒給時用 AI 工具啟動伺服器時的目前資料夾。
  - 資料夾不存在時啟動失敗，訊息說明（寫到 stderr，不影響 MCP 通訊）。
  - 規則不變：只能讀寫工作資料夾（含子資料夾）裡的 `.json` 檔；`..`、其他磁碟一律拒絕；只能蓋掉電路檔。
  - 原始碼版（`npm run mcp`）的工作資料夾仍是專案資料夾。
- 回覆裡的路徑一律寫相對於工作資料夾的路徑；伺服器說明（instructions）寫出工作資料夾的完整路徑，AI 才知道檔案存在哪裡。
- 新工具 `list_files`：列出工作資料夾裡的電路檔（最多往下 3 層，略過 `node_modules`、`.git` 與 `.` 開頭的資料夾；最多 100 個），
  每個寫出麵包板種類、元件數、有沒有邏輯圖、有沒有題目。不是電路檔的 `.json` 不列。

## 4. 真值表題目的工具

題目的資料和網頁一樣（`LogicDiagram.task`，子專案 24、32）：輸入名稱（第一個是最高位元）、輸出名稱、每一列的值，
輸出可以是 7 段顯示器（格子 0–15）。現有的函式（`src/logic/task.ts`、`design.ts`、`diagramCheck.ts`）直接拿來用，不另寫一套。

| 工具 | 做什麼 |
|---|---|
| `task_set` | 寫入（取代）題目，三種用法只能選一種：`inputs`（名稱陣列）+ `outputs`（每個輸出一個物件，見下）；`from_diagram: true` 用檔案裡邏輯圖的真值表建立；`clear: true` 刪除題目。邏輯圖不動。輸入、輸出個數的上限和網頁一樣。 |
| `task_show` | 列出題目的真值表，以及每個輸出化簡後的布林式（`form` 可選 `sop` 積項和（預設）、`pos` 和積）。 |
| `task_to_diagram` | 照題目產生邏輯圖，取代檔案裡的邏輯圖（題目保留；原本有邏輯圖時回覆裡說明取代了幾個元件）。`form`：`sop`（預設）、`pos`、`nand`、`nor`。回覆每個輸出的布林式、閘的數量與比對結果。 |
| `task_check` | 拿題目和檔案裡的邏輯圖、麵包板比對（有哪個就比哪個）；列出不一致的列（最多 10 列，再多寫「還有 N 列」）或還不能比對的原因。 |

`task_set` 的 `outputs`，每個輸出是下面其中一種：

- 一般輸出：`{ name, ones: [列號…], dont_care?: [列號…] }`（列號從 0 開始，和網頁「1 的列」「不在乎的列」一樣；其他列是 0；`ones` 可以是空的）。
- 7 段顯示器：`{ name, display: true, values: [每一列的值…] }`，值是 0–15 或 `"X"`，個數要剛好等於列數。

錯誤照網頁的說法回覆（例如名稱不合法、列號超出範圍、個數不對），檔案不變。

- 現有工具的小修正：存檔時題目不能遺失。目前 `scripts/mcp-server.ts` 在邏輯圖沒有節點時不存 `logic`，
  只有題目的檔案會把題目丟掉；改成照 `toCircuitFile` 的規則（有節點、題目或便條就存）。
- 伺服器說明加上題目的流程：`task_set` → `task_show` → `task_to_diagram` → `logic_to_breadboard` → `task_check`。

## 5. 打包與發布

- `npm run build:mcp`：把 `scripts/mcp-server.ts` 和它用到的所有東西（MCP SDK、zod、核心引擎、元件定義 JSON）
  打包成 `dist-mcp/breadboard-lab-mcp.mjs`（ES module，目標 Node.js 22 以上；實作時從 20 改成 22：20 已在 2026-04 停止支援，CI 用 22 測）。用專案已有的 Vite（不新增建置工具）。
  檔頭註解寫出名稱、網站網址、建置的 commit 與日期。
- 伺服器的版本號用建置的日期（例如 `2026.10.19`），原始碼版維持 `1.0.0`。`node breadboard-lab-mcp.mjs --version` 印出版本。
- `npm run publish:site` 多做四件事：
  1. 執行 `build:mcp`，把檔案放到網站的 `mcp/breadboard-lab-mcp.mjs`。
  2. 放上設定說明頁 `mcp/index.html`（見第 6 節）。
  3. 檢查打包檔與說明頁裡沒有作者的 Email：這個 repo 所有 commit 的作者與提交者 Email（從 `git log` 取得）和 `git config user.email`，
     GitHub 匿名信箱也算；找到就停止發布、說明在哪個檔案。（只比對這些 Email，不用「像 Email 的字串」，免得套件裡的範例字串誤擋。）
  4. 網站 repo 的 README 加上打包檔與設定說明頁的網址。
- 網頁「說明」選單加一項「給 AI 工具用（MCP）」，打開網站上的設定說明頁（離線版也連到網站的網址）。

## 6. 設定說明頁

一頁繁體中文的靜態網頁（和網站同樣的深色風格，手機也能看），內容：

1. 這是什麼：讓 AI 工具幫你放元件、接線、檢查、佈線、模擬、畫邏輯圖、出真值表題目；結果存成網頁能匯入的 `.json` 檔。
2. 需要：Node.js 22 以上（附官網連結與檢查版本的指令 `node --version`）。
3. 下載 `breadboard-lab-mcp.mjs`，放在固定的位置（例如 `C:\tools\` 或 `~/tools/`），再準備一個放電路檔的資料夾。
4. 每個 AI 工具一段照著貼的設定，Windows 與 macOS 的路徑各一個例子：
   Cursor、VS Code（Copilot 的 agent 模式）、Gemini CLI、Claude Desktop、Claude Code。
   設定檔的位置與格式**實作時照各工具目前的官方文件寫**，並寫上查證的日期。
5. 第一次可以怎麼問（三、四個例子，包含題目的流程）。
6. 結果怎麼看：在網頁用「檔案 → 匯入 JSON」打開。
7. 更新：重新下載檔案蓋掉舊的，重新啟動 AI 工具；版本號怎麼看。
8. 常見問題：找不到 node、工具沒有出現（重新啟動 AI 工具）、檔案存到哪裡。

## 7. 測試

- 單元測試（`tests/mcp/tools.test.ts` 或新的檔案）：四個題目工具的成功與每一種錯誤、只有題目的檔案存檔再讀回來題目還在、
  `list_files` 的過濾（非電路檔、太深、略過的資料夾）、工作資料夾的路徑規則。
- 整合測試：
  - 現有的 `tests/mcp/server.test.ts` 改成 19 個工具，並加上題目的流程（`task_set` → `task_to_diagram` → `task_check` 全部一致）。
  - 新增：執行 `build:mcp`，用 `node dist-mcp/breadboard-lab-mcp.mjs --folder <暫存資料夾>` 啟動，在**原始碼資料夾以外**建立電路檔、
    跑一次題目流程；`--version` 印出版本；資料夾不存在時啟動失敗。
- 發布檢查：Email 檢查的函式有單元測試（找到 / 找不到）。
- 端對端：「說明」選單的新項目連到設定說明頁的網址。
- 設定說明頁裡的設定，實作完至少在一個 AI 工具上真的試過一次（本機有的 Claude Code，用打包檔與 `--folder` 設定）。

## 8. Claude 做的決定（使用者看規格時可以改）

- 主要對象是 Cursor、VS Code 的 Copilot、Gemini CLI，Claude Desktop 與 Claude Code 也附設定（使用者選了「給會寫程式的人、多個工具」）。
- 檔案放在公開的網站 repo，不發布到 npm、不做 Claude Desktop 安裝包（使用者同意的方向）。
- 工作資料夾用 `--folder` 指定，沒給就用目前資料夾。
- 新增 `list_files`；題目工具分成四個（`task_set`、`task_show`、`task_to_diagram`、`task_check`），參數照網頁的「1 的列」「不在乎的列」設計。
- 版本號用建置日期。
- 網頁「說明」選單加一個連到設定說明頁的項目。
- 說明頁只有繁體中文。

## 9. 留給實作的決定

- 打包的細節（Vite 的 SSR / library 設定、要不要壓縮）、版本號從哪裡注入。
- 說明頁怎麼產生（放在 `public/` 跟著網站建置，或由發布程式寫出），只要內容與網址符合第 5、6 節。
- `task_show` 真值表的排版、`list_files` 的排序（照路徑）。
