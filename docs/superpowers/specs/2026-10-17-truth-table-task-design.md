## 0. 目的

老師出題常常只給一張真值表。現在要先畫出邏輯圖，才能和麵包板比對。這個子專案讓人直接輸入一張真值表當「題目」，然後：

1. 畫出來的邏輯圖可以和題目比對（設計對不對）；
2. 接好的麵包板也可以和題目比對（接得對不對），方法和子專案 22 一樣：依名稱對應開關、LED，逐列模擬。

題目跟著專案存（同一個電路檔），老師可以把含題目的檔案發給學生。

## 1. 決定

| 項目 | 決定 |
|---|---|
| 題目放哪裡 | 邏輯圖畫面右側多一個分頁「題目」（屬性、真值表、題目、檢查） |
| 存在哪裡 | 邏輯圖資料的 `task` 欄位（電路檔的 `logic.task`）；邏輯圖的 Undo / Redo 也包含題目的修改 |
| 輸入 | 1–6 個名稱（最多 64 列）；第一個是最高位元，列從全 0 數到全 1（和現在的真值表一樣） |
| 輸出 | 1–8 個名稱，每格是 0、1 或 X（不在乎，不比對） |
| 名稱規則 | 和邏輯圖一樣：英文字母開頭、英數或底線、最多 8 個字；輸入、輸出之間也不能重複 |
| 輸入的方法 | 點表格的輸出格依序換 0 → 1 → X；或在每個輸出下面輸入「1 的列」與「不在乎的列」（列號，Σm 的寫法） |
| 從邏輯圖建立 | 有邏輯圖時可以「用目前邏輯圖的真值表建立題目」（老師畫好答案就能產生題目）；邏輯圖要能算真值表、輸出都是輸出端、沒有不確定的格子 |
| 和邏輯圖比對 | 依名稱：題目的每個輸入要有同名的輸入端、每個輸出要有同名的輸出端；邏輯圖多出來的輸入端也算對不上（它的值會影響結果）；多出來的輸出端不管 |
| 和麵包板比對 | 依名稱，和子專案 22 相同（開關名稱 = 輸入名稱，LED 名稱 = 輸出名稱；開關接 +5 V 時 ON = 1、接 GND 時 ON = 0） |
| 不在乎的格子 | 兩種比對都跳過 |
| 不做（之後再說） | 從題目自動產生邏輯圖（化簡、布林式）、輸出是 7 段顯示器的題目、MCP 工具、一個專案多張題目 |

## 2. 資料（`src/logic/task.ts`）

```ts
export type TaskValue = 0 | 1 | 'X';

export interface TruthTask {
  /** 輸入名稱，第一個是最高位元。 */
  inputs: string[];
  /** 輸出名稱。 */
  outputs: string[];
  /** rows[r][k]：第 r 列（輸入照二進位從全 0 數到全 1）第 k 個輸出的值。 */
  rows: TaskValue[][];
}
```

`LogicDiagram` 加上 `task?: TruthTask`。邏輯圖的編輯函式都用 `{ ...d, … }` 產生新的圖，所以會保留題目。

- 讀檔（`parseLogicDiagram`）：`task` 格式不對就整個邏輯圖拒絕並說明原因（和其他欄位一樣）。檢查：名稱規則、數量範圍、不重複、
  `rows` 剛好 2^輸入數 列、每列剛好輸出數個值、值只能是 0、1、"X"。
- 存檔：邏輯圖沒有元件但有題目時也要存（`toCircuitFile`）；「有沒有未儲存的修改」也要算題目（`logicDirty`）。

純函式：

- `parseNames(text)`：用空白或逗號分開的名稱 → 名稱陣列或錯誤訊息。
- `createTask(inputs, outputs)`：檢查後建立，輸出全部是 0。
- `cycleCell(task, row, k)`：0 → 1 → X → 0。
- `rowsWith(task, k, value)`：第 k 個輸出是某個值的列號（顯示「1 的列」「不在乎的列」）。
- `parseRowList(text, rowCount)`：「1, 2, 4, 7」→ 列號；超出範圍、不是整數、重複都回傳錯誤訊息。
- `setColumn(task, k, ones, dontCares)`：第 k 個輸出改成這些列是 1、這些列是 X、其他是 0；兩邊有同一列是錯誤。
- `renameTask(task, inputs, outputs)`：輸入的個數不變時保留值、只換名字；輸入個數改變時每列重新開始（輸出全 0）。
  輸出依名稱保留（同名的輸出留著它的值，新的輸出全 0）。
- `taskFromDiagram(d)`：用邏輯圖的真值表建立題目，不能建立時回傳原因。
- `compareDiagramToTask(d, task)`：見第 3 節。

## 3. 題目分頁（`src/components/Logic/TaskTab.tsx`）

**沒有題目時**：一句說明、兩個輸入欄（「輸入名稱」例如 `A B C`、「輸出名稱」例如 `X Y`）與「建立題目」按鈕；
有邏輯圖時多一個「用邏輯圖的真值表建立」按鈕。名稱有錯時在欄位下方說明。

**有題目時**：

- 表格：第一欄是列號（0 起算，灰色），接著輸入欄、輸出欄；點輸出格換值（0 藍、1 紅、X 灰，和真值表分頁的顏色一樣）。
- 每個輸出一行：「X：1 的列 [1, 2, 4, 7]　不在乎 [3]」，兩個文字欄按 Enter 或離開欄位就套用；有錯時顯示原因、不套用。
- 「改名稱」：打開兩個名稱欄（預填目前的名稱）與「套用」按鈕（規則見 `renameTask`）；「刪除題目」。
- 每次修改都進邏輯圖的 Undo（名稱例如「題目：X 第 3 列改成 1」）。

**和邏輯圖比對**（表格下方；邏輯圖沒有元件時不顯示）：

```ts
export type TaskComparison =
  | { kind: 'issues'; issues: string[] }       // 名稱對不上、迴圈、輸入太多
  | { kind: 'done'; rows: number; mismatches: Array<{ row: number; inputs: string; expected: string[]; actual: string[] }> };
```

- 名稱對不上時列出原因，例如「題目的輸入 C 在邏輯圖找不到輸入端」「題目的輸出 Y 在邏輯圖找不到輸出端」
  「邏輯圖的輸入端 D 不在題目裡」「Y 在邏輯圖是 7 段顯示器，題目的輸出要接輸出端」。
- 全部一致：「8 種輸入組合，邏輯圖和題目全部一致」（有不在乎的格子時加上「不在乎的格子不比」）。
- 不一致：「有 N 列不一致」，列出前 8 列：「A B C = 0 1 1：題目 X = 1，邏輯圖 X = 0」；邏輯圖的值不確定時寫 `?`。
  點一列：把邏輯圖的開關設成那一列（`setInputs`），在畫布上直接看。

## 4. 麵包板比對（`src/logic/diagramCheck.ts`）

- 把 `bindByLabels` 拆成不依賴邏輯圖的 `bindByNames(io, circuit)`：`io` 是輸入（id、名稱）與輸出（id、名稱、是不是顯示器）。
  邏輯圖的比對照舊用節點；題目的比對用名稱當 id。
- `checkAgainstTask(task, circuit)` 回傳和 `checkAgainstDiagram` 一樣的 `DiagramCheck`（none / hint / incomplete / done）。
- `verifyRows` 的核心改成吃「每列的輸入與期望值」：期望值 `X` 的格子不比（顯示時寫 X）。邏輯圖的比對行為不變。
- 麵包板「檢查」分頁：在「和邏輯圖的真值表比對」卡片下面多一張「和題目比對」卡片，樣子和互動都一樣
  （提示文字改成「把開關、LED 的名稱設成題目上的名稱」）。點不一致的一列：撥好開關、開始模擬；
  復原步驟的名稱用題目的輸入名稱（`applyDiagramRow` 加一個名稱參數）。

## 5. 測試

- 單元（`tests/logic/task.test.ts`）：建立與名稱錯誤、換值、1 的列與不在乎的列（解析、套用、錯誤）、改名稱（保留 / 重新開始）、
  從邏輯圖建立（成功、有顯示器、不確定的格子）、和邏輯圖比對（一致、不一致、不在乎、名稱對不上、多的輸入端、迴圈）、
  讀檔與存檔（來回、格式不對拒絕、只有題目也存、`logicDirty`）。
- 單元（`tests/logic/diagramCheck.test.ts`）：手接的 AND 電路和題目比對（AND 一致、OR 不一致、不在乎的格子不比、名稱對不上）。
- 端對端（`e2e/truth-table-task.spec.ts`）：建立 A B C / X 的題目，用「1 的列」輸入多數決（3, 5, 6, 7）；載入範例「多數決電路」
  → 題目分頁顯示全部一致；點一格改值 → 1 列不一致；轉成麵包板 → 檢查分頁的「和題目比對」全部一致；重新整理後題目還在（自動保存）。
