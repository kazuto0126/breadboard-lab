# AI 解說（子專案 5，第一部分：離線錯誤解說）設計規格

- 日期：2026-10-08
- 狀態：設計中
- 需求文件：第十六章（AI 負責分析、解釋錯誤、建議最佳化，不直接畫線）、第三十七章（自動偵錯、AI Circuit Assistant）
- 範圍：這份只做**不用網路**的錯誤解說；接 Claude API（使用者自己貼金鑰）之後另寫一份規格

---

## 0. 目的

數位邏輯實驗課的學生按「Check Circuit」後，只看到「U1 第 14 腳 VCC 未連接」這種訊息，常常不知道為什麼錯、要插哪個孔。
這個功能在學生點一個錯誤時，說明**為什麼錯**，並給出**具體到孔位**的修改步驟，同時在麵包板上用綠色標出建議的孔與導線。
學生照著做就能改好，接實體麵包板時也知道該怎麼插。

## 1. 決定

| 項目 | 決定 |
|---|---|
| 範圍 | 電路檢查的 17 種錯誤 / 警告（`CIRCUIT_VALID` 除外）都有「為什麼」與「怎麼改」；其中 7 種有具體孔位建議（第 3 節） |
| 計算方式 | 確定性的規則，同一個電路永遠得到同樣的解說；不用網路、不用金鑰 |
| 何時計算 | 只在學生選取一個錯誤時，針對那一個錯誤計算（`selection = { kind: 'issue' }`）；核心的 `validateCircuit` 不改 |
| 自動修正 | 不做。只給建議，學生自己接線 |
| 建議導線的路徑 | 用手動接線同一個路徑規劃 `planWirePath`，學生從建議的起點拉到終點，會得到同一條線 |
| 出錯時 | 某個解說函式丟出例外時，退回那種錯誤的通用說明（只有文字、不標孔位），面板不會壞掉 |
| 多塊板 | 孔位名稱沿用 `holeLabel`（多塊板時是 `b2:A12`）；建議的孔一律在問題所在的那塊板上 |

## 2. 畫面

### 2.1 解說卡

「檢查」分頁裡點一個錯誤（目前會選取它、把畫面移過去），那一項下面展開解說卡；右側「屬性」分頁選到錯誤時也顯示同一張卡。

```
⚠ U1（74LS00）第 14 腳 VCC 未連接
為什麼：74LS 晶片要從 VCC 腳拿 +5 V 才會動作；這隻腳沒有接到 VCC，整顆 IC 都不會工作。
怎麼改：
 ① 從 U1 第 14 腳那一排的空孔 [A16]，拉一條線到上方的 + 電源軌 [T+16]。
（綠色虛線是建議的導線）
```

- 卡片標題是原本的錯誤訊息；「為什麼」一到三句；「怎麼改」是有編號的步驟。
- 步驟裡的孔位是按鈕（`[A16]`），點了畫面移到那個孔（`focusPoints`）。
- 有建議要拔掉的導線時，步驟寫出導線 ID 與兩端孔位，例如「先拔掉 m3（T+12 → B-12）」。
- 卡片 `data-testid="explanation"`，步驟清單是 `<ol>`。

### 2.2 板上標示

選取錯誤時，除了現在的紅 / 黃標記，再加上：

- 建議的孔：綠色虛線圈，旁邊標編號（1、2、3…，和步驟裡第一次出現的順序一致）。
- 建議的導線：綠色虛線預覽（沿用接線時的 `PathPreview` 樣式）。
- 建議拔掉的導線：沿用紅色光暈（`WireGlow`），不另外加顏色。
- 標示放在 `<g data-ui="explanation">`，建議的孔有 `data-suggested-hole="A16"`。

## 3. 每種錯誤的解說

共用的規則：

- **電源軌選擇**：IC 的腳在上半部（A–E）時用上方的軌（`T+` / `T-`），下半部（F–J）用下方的軌（`B+` / `B-`）。
  如果那條軌沒有接到需要的電源，但同一塊板的另一條同極性的軌有，就改用那一條。兩條都沒有時，用腳那一側的軌，並在最前面加一步
  「先放一個 VCC（或 GND）到這條軌上，例如 [T+3]」（選那條軌 x 最小的空孔）。
- **從腳拉線**：起點是腳所在導通排（同一欄的 A–E 或 F–J）裡、最靠近目標軌的空孔（上半部選 y 最小，下半部選 y 最大）；
  終點是目標軌上和起點 x 最接近的空孔（同距離選 x 較小的）。導線路徑用 `planWirePath(circuit, 起點, 終點, 'v')`。
- **找不到空孔**時照實說明，例如「U1 第 14 腳那一排已經沒有空孔，請先移開那一排上的導線或元件」，不標孔位。

### 3.1 有具體孔位建議的 7 種

| 錯誤 | 為什麼 | 怎麼改（孔位） |
|---|---|---|
| `IC_POWER_MISSING` | 74LS 晶片要從 VCC 腳拿 +5 V、從 GND 腳接地才會動作；這隻腳沒接上，整顆 IC 都不會工作 | 從那隻腳的排拉線到 + 軌（VCC 腳）或 − 軌（GND 腳）；沒有電源元件時先放一個 |
| `NO_POWER_SOURCE` | 電路裡沒有 VCC 和 GND，任何元件都拿不到電 | 放一個 VCC 到 `T+` 軌、一個 GND 到 `B-` 軌（各選 x 最小的空孔），再把用到電的元件接到這兩條軌 |
| `INPUT_FLOATING` | TTL 輸入腳空著時會被當成 HIGH，但很容易受雜訊干擾，結果不穩定 | 要用的話接到開關或其他閘的輸出；**用不到的話**，從那隻腳的排拉線到 + 軌（標出這條建議線） |
| `PIN_UNCONNECTED` | 這隻腳所在的那一排只有它自己，電流沒有路可走 | 標出那一排最靠近中間凹槽的空孔，說明「從這裡拉線到要接的地方」 |
| `LED_NO_RESISTOR` | LED 直接接在電源上電流太大，會燒掉 LED 或 IC 的輸出腳；要串一顆 220–330 Ω 的電阻限流 | 把電阻串在 LED 陰極那一側（第 3.2 節）：電阻兩腳的孔都標出；陰極那一排原本接出去的導線，改接到電阻另一腳那一排 |
| `LED_REVERSED` | LED 只能單向導通：陽極（長腳）要接高電位、陰極（短腳）接 GND；現在接反了，LED 不會亮 | 把 LED 旋轉 180°（選取後按兩次 R）；標出陽極、陰極現在的位置 |
| `SHORT_CIRCUIT` | 電源沒有經過任何元件就直接接到 GND（或接到不同電壓的電源），電流非常大，電源會過熱或啟動保護 | 逐一假設拔掉這個 Net 上的每一條導線，重新算 Net；拔掉後就不再短路的導線列為「建議先拔掉」（附兩端孔位）。找不到這種導線時（例如元件腳直接插在一起），說明要移開哪個元件 |

### 3.2 LED 限流電阻放哪裡

1. 電阻（元件庫的 220 Ω，兩腳相距 4 孔、水平）一腳插在 LED 陰極那一排的空孔，另一腳插在同一列往左或往右 4 格的孔。
   依序試陰極那一排的每個空孔（離中間凹槽近的先試）、先往右再往左，選第一個：用 `checkPlacement` 確認放得下，
   而且另一腳那一排**整排沒有任何腳或導線端點**（新的一排，不會接到別的東西）。
2. 陰極那一排原本有導線接出去時：每一條都寫成一步「把 m3 插在 [E30] 的那一端拔起來，改插到 [D34]」（[D34] 是電阻另一腳那一排的空孔），
   這幾條列進 `removeWireIds`，改接後的新路徑（`planWirePath`）列進 `wires`。
3. 陰極那一排沒有導線、也沒有其他腳時：加一步從電阻另一腳那一排拉線到 GND 軌（同第 3 節的「從腳拉線」規則）。
4. 陰極那一排直接插著其他元件的腳（沒有導線可以改接），或第 1 步找不到位置：只給文字「先把 LED 移到旁邊空的位置，再串電阻」，不標孔位。

### 3.3 其他 10 種（只有文字，板上沿用現在的紅 / 黃標記）

| 錯誤 | 為什麼 | 怎麼改 |
|---|---|---|
| `PLACEMENT_INVALID` | 元件有腳沒插在孔上，或兩腳距離太小，實體元件插不進去 | 把元件拖到每隻腳都在孔上的位置；電阻 / LED 可以在屬性面板加長兩腳距離 |
| `PIN_COLLISION` | 一個孔只能插一隻腳或一條線，兩個東西擠在同一孔實際上插不進去 | 移開其中一個元件或導線，改插同一排的其他空孔（同一排是導通的，接法不變） |
| `BODY_OVERLAP` | 兩個元件的本體疊在一起，實體上放不下 | 把其中一個元件移到旁邊空的位置 |
| `WIRE_ENDPOINT_INVALID` | 導線的端點要插在空孔上：不能在板面、元件下面，也不能和別條線插同一孔 | 刪掉這條線，從空孔重新拉一條；要接同一排時改用同一排的其他空孔 |
| `WIRE_PATH_INVALID` | 導線路徑要沿著孔走、只能水平或垂直轉彎（通常是舊檔案或手動編輯的檔案造成） | 刪掉這條線重新拉 |
| `WIRE_THROUGH_OBSTACLE` | 跳線平貼在板上，不能壓過元件的腳、本體或別條線的端點 | 刪掉這條線重新拉，接線時會自動繞開；或按「AI 標準佈線」 |
| `WIRE_OVERLAP` | 兩條線在板上疊在同一段，實際上插不下，也很難看出誰接誰 | 刪掉其中一條改走別的路，或按「AI 標準佈線」重新排 |
| `IC_PIN_SHORT` | IC 的兩隻腳插在同一條導通排上，等於被接在一起（通常是 IC 沒有跨在中間凹槽上） | 把 IC 移到跨過中間凹槽的位置，讓上下兩排腳分開 |
| `OUTPUT_CONFLICT` | 兩個輸出腳接在一起（或輸出腳直接接電源），兩邊各自想送 HIGH / LOW 會互相打架，可能燒壞 IC | 一個 Net 只能有一個輸出；拔掉多出來的那條連線，必要時改用邏輯閘合併 |
| `COMPONENT_SHORTED` | 元件的兩隻腳插在同一條導通排上，電流直接從排上流過，元件等於沒接 | 把元件轉 90° 或移位置，讓兩隻腳在不同的排 |

## 4. 程式

```text
src/editor/explain/
  types.ts        Explanation、ExplainStep
  helpers.ts      pinAt、freeHolesInGroup、railHoles、railCarries、suggestWireFromPin
  power.ts        IC_POWER_MISSING、NO_POWER_SOURCE、INPUT_FLOATING
  parts.ts        PIN_UNCONNECTED、LED_NO_RESISTOR、LED_REVERSED
  short.ts        SHORT_CIRCUIT
  generic.ts      第 3.3 節的文字與每種錯誤的「為什麼」（也當作例外時的退路）
  index.ts        explainIssue(circuit, issue)：依 code 分派、try/catch、依 issue 物件快取（WeakMap）
```

```ts
export interface ExplainStep {
  text: string;
  /** 步驟裡提到的孔（畫面上變成可以點的按鈕，依出現順序）。 */
  holes: GridPoint[];
}

export interface Explanation {
  why: string;
  steps: ExplainStep[];
  /** 板上用綠色虛線圈標示並編號的孔（依步驟裡第一次出現的順序，不重複）。 */
  holes: GridPoint[];
  /** 建議的導線路徑（綠色虛線預覽）。 */
  wires: GridPoint[][];
  /** 建議拔掉的既有導線。 */
  removeWireIds: string[];
}
```

- `src/editor/explain/` 不能用 DOM（和 `src/editor/` 其他檔案一樣，`tsconfig.json` 涵蓋）。
- 畫面：`PropertyPanel` 的 `CheckTab` 與 `case 'issue'` 顯示 `ExplanationCard`；`BreadboardCanvas` 在 `selection.kind === 'issue'`
  時畫 `SuggestionMarks`（`overlays.tsx`）。

## 5. 測試

- 單元測試 `tests/editor/explain.test.ts`：用 `src/editor/builder.ts` 建小電路，每種有孔位建議的錯誤至少一個測試，檢查步驟文字裡的孔位、
  `holes`、`wires` 的兩端與 `removeWireIds`；另測：沒有空孔時的說明、沒有電源元件時多一步、軌選擇（上半部 / 下半部 / 只有另一條軌有電）、
  10 種文字錯誤都有 why 與至少一步、解說函式丟例外時退回通用說明。
- 照著建議做會修好：對 `IC_POWER_MISSING`、`INPUT_FLOATING`、`LED_NO_RESISTOR`、`SHORT_CIRCUIT`，把建議套用到電路（加上建議的導線、
  放上建議的電阻、拔掉建議的導線）後重新 `validateCircuit`，那個錯誤要消失。
- 端對端 `e2e/explain.spec.ts`：放一顆沒接電源的 74LS00 與 VCC、GND → Check Circuit → 點「第 14 腳 VCC 未連接」→ 看到解說卡與
  帶孔位的步驟、板上出現建議的孔 → 照建議從起點拉線到終點 → 那個錯誤消失。
